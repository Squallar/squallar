# Real NWS alert `event` values -- checked-in sample used by the colors.rs tests.
#
# Source 1: https://api.weather.gov/alerts/types  (the API's own enumeration of
#           every valid alert product name)
# Source 2: distinct `properties.event` values observed in a snapshot of
#           https://api.weather.gov/alerts/active
# Captured: 2026-07-25
#
# Why this file exists
# --------------------
# ALERT_COLORS is a keyword table. When NWS renames a product (as it did when
# hazard simplification replaced "Excessive Heat Warning" with "Extreme Heat
# Warning", and "Wind Chill Warning" with "Extreme Cold Warning"), the old
# keywords stop matching anything and the affected alerts silently fall through
# to the generic suffix entries -- which used to paint them tornado red. Nothing
# failed; the map just started lying.
#
# `every_live_entry_matches_a_real_event` asserts that every non-legacy row in
# ALERT_COLORS still matches at least one name below, so the next rename fails a
# test instead of silently recolouring the map.
#
# To refresh (requires a non-empty User-Agent; an empty one gets a 403):
#   curl -H 'User-Agent: squallar (you@example.com)' \
#        https://api.weather.gov/alerts/types | jq -r '.eventTypes[]' | sort
#
# Lines starting with `#` and blank lines are ignored. One event name per line.
